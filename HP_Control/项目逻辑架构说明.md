# HP_Control 项目逻辑架构说明

## 📋 项目概述

**HP_Control** 是一个**高压液压控制系统**（版本 v8.0），采用**平台无关化架构**。

### 核心设计理念

- **数据采集与执行层**：嵌入式系统只负责传感器数据采集和硬件执行
- **控制算法在PC端**：所有控制逻辑在TSMaster（PC端）运行
- **CAN通信桥梁**：通过CAN总线实现嵌入式系统与PC端的双向通信

---

## 🏗️ 系统架构

```
┌─────────────────────────────────────────────────────────────┐
│                     TSMaster (PC端)                          │
│  ┌─────────────────────────────────────────────────────┐   │
│  │  控制算法逻辑 (换向阀、旁通阀、风冷器控制)           │   │
│  └─────────────────────────────────────────────────────┘   │
│                          ↕ CAN总线                          │
└─────────────────────────────────────────────────────────────┘
                           ↕
┌─────────────────────────────────────────────────────────────┐
│                  HP_Control (嵌入式端)                       │
│  ┌──────────────┐  ┌──────────────┐  ┌──────────────┐     │
│  │  传感器模块  │  │  阀门控制模块│  │  CAN通信模块 │     │
│  │  (数据采集)  │  │  (硬件执行)  │  │  (数据传输)  │     │
│  └──────────────┘  └──────────────┘  └──────────────┘     │

    ┌─────────┐     ┌─────────┐         ┌─────────┐
    │ 传感器  │     │ 执行器  │         │ CAN收发器│
    └─────────┘     └─────────┘         └─────────┘
```

## 🔧 核心模块

### 1. 传感器模块 (`sensor.c/h`)

**功能**：四路ADC采集和数据处理

| 传感器 | 通道 | MCU引脚 | 测量范围 | 精度 |
|--------|------|---------|----------|------|
| **油温** | ADC1_IN1 | PA3 | -40°C ~ 90°C | ±1°C |
| **LNG温度** | ADC1_IN0 | PA2 | -40°C ~ 90°C | ±1°C |
| **油压** | ADC1_IN2 | PD2 | 0 ~ 40 MPa | ±0.1 MPa |
| **LNG压力** | ADC1_IN3 | PD3 | 0 ~ 40 MPa | ±0.1 MPa |

**关键函数**：
- `Sensor_Init()` - 传感器模块初始化
- `Sensor_UpdateMonitor()` - 更新所有传感器数据（包含滤波处理）
- `Sensor_GetOilTemperature()` - 获取油温（滤波后）
- `Sensor_GetLNGTemperature()` - 获取LNG温度（滤波后）
- `Sensor_GetOilPressure()` - 获取油压（滤波后）
- `Sensor_GetLNGPressure()` - 获取LNG压力（滤波后）

**数据处理流程**：
```
ADC原始值 → 电压值 → 物理量 → 滤波处理 → 输出
```

---

### 2. 阀门控制模块 (`valve_control.c/h`)

**功能**：硬件执行器控制

#### 2.1 换向阀（方向阀）
- **控制方式**：GPIO输出（PB4）
- **状态**：ON/OFF（高电平/低电平）
- **功能**：控制液压系统流向

**关键函数**：
- `ValveControl_SetDirectionalValve(bool enable)` - 设置换向阀状态
- `ValveControl_GetDirectionalValveState()` - 获取换向阀状态

#### 2.2 旁通阀
- **控制方式**：PWM输出（PWM0_CH2）
- **开度范围**：0% ~ 50%
- **功能**：调节系统压力

**关键函数**：
- `ValveControl_SetBypassValve(float duty)` - 设置旁通阀开度（0-50%）
- `ValveControl_GetBypassValveDuty()` - 获取旁通阀开度

#### 2.3 风冷器
- **控制方式**：GPIO输出（PE8）
- **状态**：ON/OFF
- **功能**：油温冷却

**关键函数**：
- `ValveControl_SetCooler(bool enable)` - 设置风冷器状态
- `ValveControl_GetCoolerState()` - 获取风冷器状态

---

### 3. CAN通信模块 (`can_config.c/h`, `gcu_control_dbc.c/h`)

**功能**：与PC端（TSMaster）进行双向CAN通信

#### 3.1 CAN配置
- **波特率**：250 Kbps
- **收发引脚**：PE4 (RX), PE5 (TX)
- **备用通道**：PE10 (ALT5)

#### 3.2 CAN消息定义（基于 `gcu_hp_control_04.dbc`）

##### 发送消息：`device_status` (ID: 0x9808FFEC)
**发送频率**：10ms周期（高优先级任务）

| 信号名称 | 位置 | 长度 | 范围 | 单位 | 说明 |
|---------|------|------|------|------|------|
| `bypass_ratio` | 0:7 | 8位 | 0-50 | % | 旁通阀开度 |
| `oil_pressure` | 8:15 | 8位 | 0-40 | MPa | 油压 |
| `oil_temperature` | 16:23 | 8位 | -40~90 | °C | 油温 |
| `LNG_temperature` | 24:31 | 8位 | -40~90 | °C | LNG温度 |
| `LNG_pressure` | 32:39 | 8位 | 0-40 | MPa | LNG压力 |
| `rev_freq` | 40:49 | 10位 | 0-1000 | min/次 | 换向频率 |
| `rev_enable` | 50:50 | 1位 | 0-1 | - | 换向阀使能 |
| `cooler_enable` | 51:51 | 1位 | 0-1 | - | 风冷器使能 |

##### 接收消息1：`tsmaster_control` (ID: 0x98080100)
**接收频率**：按需接收（IfActive模式）

| 信号名称 | 位置 | 长度 | 范围 | 单位 | 说明 |
|---------|------|------|------|------|------|
| `set_bypass_initial_decline_time` | 0:9 | 10位 | 0-100 | s | 旁通阀起始下降时间 |
| `set_rev_start_oilP_max` | 10:16 | 7位 | 0-10 | MPa | 换向启动最大油压 |
| `set_rev_start_oilP_min` | 17:23 | 7位 | 0-10 | MPa | 换向启动最小油压 |
| `set_first_fix_freq_time_on` | 24:33 | 10位 | 0-100 | s | 第一阶段固定频率开启时长 |
| `set_first_fix_freq_time_off` | 34:43 | 10位 | 0-100 | s | 第一阶段固定频率关闭时长 |
| `set_second_rev_oilP_max` | 44:52 | 9位 | 0-40 | MPa | 第二阶段换向最大油压 |
| `set_second_rev_oilP_min` | 53:61 | 9位 | 0-40 | MPa | 第二阶段换向最小油压 |

##### 接收消息2：`tsmaster_control2` (ID: 0x98080108)
**接收频率**：按需接收（IfActive模式）

| 信号名称 | 位置 | 长度 | 范围 | 单位 | 说明 |
|---------|------|------|------|------|------|
| `set_rev_compel_time_on` | 0:9 | 10位 | 0-100 | s | 强制换向开启时间 |
| `set_rev_compel_time_off` | 10:19 | 10位 | 0-100 | s | 强制换向关闭时间 |
| `system_enable` | 20:20 | 1位 | 0-1 | - | 系统使能（0=禁用，1=启用） |
| `set_cooler_temperature_on` | 21:27 | 7位 | 0-100 | °C | 风冷器开启温度阈值 |
| `set_cooler_temperature_off` | 28:34 | 7位 | 0-100 | °C | 风冷器关闭温度阈值 |
| `set_bypass_ratio` | 35:44 | 10位 | 0-50 | % | 旁通阀开度设置 |
| `set_second_on_overtime` | 45:53 | 9位 | 0-100 | s | 第二阶段换向开启超时 |
| `set_second_off_overtime` | 54:62 | 9位 | 0-100 | s | 第二阶段换向关闭超时 |

**关键函数**：
- `CAN_Config_Init()` - CAN模块初始化
- `CAN_Config_SendMessage()` - 发送CAN消息
- `CAN_RxCallback()` - CAN接收回调处理（在`main.c`中实现）
- `device_status_pack()` - 打包传感器数据
- `tsmaster_control_unpack()` / `tsmaster_control2_unpack()` - 解包控制命令

### 5. 任务调度器 (`optimized_task_scheduler.c/h`)

**功能**：多任务周期调度

**任务优先级**：
- `TASK_PRIORITY_CRITICAL` (0) - 关键任务
- `TASK_PRIORITY_HIGH` (1) - 高优先级任务
- `TASK_PRIORITY_NORMAL` (2) - 普通任务
- `TASK_PRIORITY_LOW` (3) - 低优先级任务

## ⏱️ 任务调度

系统使用**优化任务调度器**，按优先级和周期执行任务：

| 任务名称 | 周期 | 优先级 | 功能描述 |
|---------|------|--------|----------|
| **Task_1ms_CANMessageProcess** | 1ms | CRITICAL | CAN消息处理（接收回调触发） |
| **Task_10ms_SendSensorData** | 10ms | HIGH | 发送传感器数据给PC |
| ~~Task_50ms_SafetyCheck~~ | 50ms | CRITICAL | ~~安全保护检查~~（已禁用） |
| **Task_100ms_RealTimeCANMonitor** | 100ms | NORMAL | 实时CAN信号监控 |
| **Task_1000ms_CANStatusMonitor** | 1000ms | LOW | CAN通信状态监控 |
| **Task_2000ms_SensorDataMonitor** | 2000ms | LOW | 传感器数据监控（打印） |

## 🔄 系统运行流程

### 1. 系统初始化 (`SystemInit()`)

```
1. 硬件初始化 (SystemHardwareInit)
   ├─ 时钟配置
   ├─ GPIO初始化（启动开关、风冷器、换向阀）
   └─ PWM初始化（旁通阀）

2. 核心模块初始化
   ├─ Sensor_Init() - 传感器模块
   ├─ ValveControl_Init() - 阀门控制模块
   ├─ FaultDiagnosis_Init() - 故障诊断模块
   └─ CAN_Config_Init() - CAN通信模块

3. 任务调度器初始化
   └─ OptimizedTaskScheduler_Init()

4. 默认状态设置
   ├─ 风冷器：OFF
   ├─ 换向阀：OFF
   ├─ 旁通阀：0%
   └─ 系统使能：ON（强制开启）
```

### 2. 主循环 (`main()`)

```
while (1) {
    1. 执行任务调度 (OptimizedTaskScheduler_MainLoop)
       ├─ 按优先级顺序执行任务
       └─ 检查任务周期，执行到期任务
    
    2. CAN错误检测和恢复（每5000ms）
       └─ 如果错误过多，重置CAN控制器
}
```

### 3. 数据采集流程（10ms周期）

```
Task_10ms_SendSensorData() {
    1. 更新传感器数据 (Sensor_UpdateMonitor)
       └─ ADC采集 → 电压转换 → 物理量转换 → 滤波处理
    
    2. 填充CAN消息 (device_status_t)
       ├─ 油温 (oil_temperature)
       ├─ LNG温度 (LNG_temperature)
       ├─ 油压 (oil_pressure)
       ├─ LNG压力 (LNG_pressure)
       ├─ 旁通阀开度 (bypass_ratio)
       ├─ 换向阀状态 (rev_enable)
       ├─ 风冷器状态 (cooler_enable)
       └─ 换向频率 (rev_freq)
    
    3. 编码和打包 (device_status_pack)
       └─ 物理值 → 原始CAN值
    
    4. 发送CAN消息 (CAN_Config_SendMessage)
       └─ 发送给PC端（TSMaster）
}
```

### 4. 控制命令接收流程（CAN中断回调）

```
CAN_RxCallback(msg_id, data, length) {
    if (msg_id == tsmaster_control) {
        1. 解包消息 (tsmaster_control_unpack)
        2. 处理控制参数（暂时只接收，不直接使用）
           ├─ set_bypass_initial_decline_time
           ├─ set_rev_start_oilP_max/min
           ├─ set_first_fix_freq_time_on/off
           └─ set_second_rev_oilP_max/min
    }
    else if (msg_id == tsmaster_control2) {
        1. 解包消息 (tsmaster_control2_unpack)
        2. 处理系统使能 (system_enable)
           └─ 如果禁用，关闭所有执行器
        
        3. 如果系统使能：
           ├─ 设置旁通阀开度 (set_bypass_ratio)
           │  └─ ValveControl_SetBypassValve()
           │
           ├─ 设置风冷器温度阈值（接收参数，实际控制由PC端完成）
           │  ├─ set_cooler_temperature_on
           │  └─ set_cooler_temperature_off
           │
           └─ 其他控制参数（接收但不直接使用）
              ├─ set_rev_compel_time_on/off
              └─ 换向阀控制（由PC端通过其他方式控制）
    }
}
```

### 5. PC端控制逻辑（TSMaster MiniProgram）

**注意**：以下逻辑在PC端运行，不在嵌入式系统中

```
PC端控制流程（示例）：
1. 接收传感器数据 (device_status)
   └─ 从嵌入式系统接收实时传感器数据

2. 执行控制算法
   ├─ 换向阀控制（基于油压）
   ├─ 旁通阀控制（基于油压和目标压力）
   └─ 风冷器控制（基于油温，滞回控制）

3. 发送控制命令
   ├─ tsmaster_control - 发送控制参数
   └─ tsmaster_control2 - 发送控制参数和系统使能
```

## 🔐 系统使能控制

### 启动开关（PC17）
- **当前状态**：**强制开启**（`FORCE_START_SWITCH_ON = 1`）
- **功能**：理论上可以控制整个系统使能（当前被强制覆盖）
- **位置**：`IsStartupSwitchActive()` 函数

### CAN系统使能（`system_enable`）
- **来源**：从PC端（TSMaster）通过`tsmaster_control2`消息接收
- **功能**：
  - `system_enable = 0`：禁用系统，关闭所有执行器
  - `system_enable = 1`：启用系统，允许PC端控制

**安全逻辑**：
```c
if (system_enable == 0) {
    // 禁用系统，安全关闭所有执行器
    ValveControl_SetBypassValve(0.0f);
    ValveControl_SetDirectionalValve(false);
    ValveControl_SetCooler(false);
    g_systemEnabled = false;
}
```

## 🔍 关键设计决策

### 1. 平台无关化架构

**原因**：
- 控制算法在PC端更容易开发和调试
- 嵌入式系统专注于硬件接口和实时数据采集
- 降低嵌入式系统的复杂度

**影响**：
- 嵌入式系统不执行控制逻辑，只执行命令
- 安全保护功能已禁用（由PC端控制）

### 2. CAN通信设计

**发送频率**：
- `device_status`：10ms周期（高优先级）
  - 原因：PC端需要实时传感器数据来执行控制算法

**接收模式**：
- `tsmaster_control` / `tsmaster_control2`：IfActive模式（按需发送）
  - 原因：控制命令不需要高频发送，只在参数变化时发送

### 3. 任务调度优化

**1ms CAN消息处理**：
- 原因：确保CAN接收回调及时处理，避免消息丢失

**10ms 传感器数据发送**：
- 原因：提供足够的实时性，同时不会过度占用CAN总线带宽

### 4. 系统使能控制

**双重使能机制**：
1. **启动开关**（硬件）：当前强制开启
2. **CAN系统使能**（软件）：由PC端控制

**安全设计**：
- 如果`system_enable = 0`，立即关闭所有执行器
- 提供紧急停止功能

## 🎯 总结

### 系统特点

1. **架构清晰**：数据采集与执行分离，控制算法在PC端
2. **实时性强**：10ms传感器数据发送，1ms CAN消息处理
3. **可维护性好**：模块化设计，职责明确
4. **扩展性强**：易于添加新的传感器或执行器

### 工作流程

1. **数据采集**：4路ADC采集 → 滤波处理 → CAN发送（10ms周期）
2. **命令接收**：CAN接收 → 解包 → 执行硬件控制（按需）
3. **控制逻辑**：在PC端（TSMaster）执行，通过CAN发送控制命令

### 关键要点

- **嵌入式系统**：只负责数据采集和硬件执行，不执行控制逻辑
- **PC端**：执行所有控制算法，通过CAN总线与嵌入式系统通信
- **CAN通信**：双向通信，10ms周期发送传感器数据，按需接收控制命令
